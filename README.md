## Versioning

All projects in this repository follow `x.y.z` (major.minor.patch):

- **patch (`z`)** — every patch/commit bumps `z`.
- **minor (`y`)** — every feature or addition; a minor bump requires explicit
  confirmation before it is applied.
- **major (`x`)** — stays static at 0 until we have a first release-ready
  version.

See `xcp-bundle-analyzer/RELEASE_NOTES.md` for the per-version history of the
analyzer.

## File headers (mandatory)

Every script and core source file (`.sh`, `.py`, `.rs`, and Debian maintainer
scripts such as `packaging/postinst`/`prerm`) must start with the standard
open-source header: 4 comment lines placed after the shebang (`#` for
shell/Python, `//` for Rust; the shebang stays on line 1):

    # <file-name> - <one-line purpose>
    # Author: eveane & Vibe Mistral
    # Date: <YYYY-MM-DD, date of the change>
    # Open source: <license statement>

The license statement matches the subproject:

- `xoa-support/**`: `Open source: GPL-2.0-only: free software under the GNU General Public License v2, as-is without warranty; see xoa-support/LICENSE`
- `xcp-bundle-analyzer/**`: `Open source: LGPL-2.1: free software under the GNU Lesser General Public License v2.1, as-is without warranty; see xcp-bundle-analyzer/Cargo.toml`
- scripts at the repository root: `Open source: free to use, modify and share, as-is without warranty; see the repository README`

Agents: add this header to every new script/core file and keep it intact when
editing existing ones; never change an existing header's author line.

## Bugtool collector

`bugtool_collector.sh` collects the `xen-bugtool` archive of every host of an
XCP-ng pool over SSH and packs them into one archive named
`<pool name or master IP>-<UTC date-time>.tar.gz`.

Usage:

```
./bugtool_collector.sh [-j N] <pool_master_ip>     # -j N: max hosts in parallel (default 3, 0 = all at once)
```

It checks its OS package dependencies itself and installs the missing ones
automatically: `dpkg -s` / `apt-get` on Debian-based hosts (the XOA), `rpm -q`
/ `dnf`/`yum` on XCP-ng hosts.

### Install on the XOA (Debian package)

A self-contained `.deb` is published as a GitHub Release
(`bugtool-collector-v<VERSION>`) on every merge to `main` that changes
`bugtool-collector/` — same pattern as `xoa-support`:

```
wget https://github.com/eveane/XCP-ng-toolbox/releases/latest/download/bugtool-collector_*_all.deb
sudo dpkg -i bugtool-collector_*_all.deb     # installs /usr/bin/bugtool-collector
sudo bugtool-collector -j 3 10.0.0.1
```

See [bugtool-collector/README.md](bugtool-collector/README.md) for details.

## v2v vm disk progress

### How to Use

Save the script as vm_disk_progress.sh.
Make it executable:

`chmod +x vm_disk_progress.sh`

Run it with the VM name:

`sudo ./vm_disk_progress.sh myVm`

## xcp-bundle-analyzer

Rust CLI to analyze status-report bundles generated by xen-bugtool (XCP-ng / XenServer).
Parses the bundle (tar/tar.gz/tar.bz2/zip), makes xapi-db.xml usable (hosts, SRs, VDIs,
VMs, VIFs, PIFs, PBDs, dom0 config) and outputs text, JSON or a self-contained HTML
dashboard. Supports a consolidated pool view when several bundles are given.
See `xcp-bundle-analyzer/README.md`.

### Install xcp-bundle-analyzer (prebuilt binaries)

Pre-compiled binaries for Linux (tar.gz / .deb / .rpm), Windows (.zip) and macOS
(tar.gz) are published as a GitHub Release (`xcp-bundle-analyzer-v<VERSION>`)
on every merge to `main` that changes `xcp-bundle-analyzer/`:

```
wget https://github.com/eveane/XCP-ng-toolbox/releases/latest/download/xcp-bundle-analyzer_*_amd64.deb
sudo dpkg -i xcp-bundle-analyzer_*_amd64.deb     # installs /usr/bin/xcp-bundle-analyzer
xcp-bundle-analyzer analyze XenServer-host1-20260616.tar.bz2
```

## xoa-support

GPL-2.0-only toolkit to collect, scrub, optionally anonymise and inspect support
bundles from a Xen Orchestra Appliance (XOA), for airgapped troubleshooting.
Includes a sos report plugin (`sos report -o xoa`), a no-dependency standalone
collector, a strict scrubber/anonymiser (`xoa_scrub.py`) and a bundle inspector
(text/JSON). See `xoa-support/README.md` and `xoa-support/docs/`.
